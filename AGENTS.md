# TAMS — Time Stats Report Import

## Goal

Add an **Import Time Stats** feature to the supervisor dashboard that allows a supervisor to upload the Excel report generated by `time_stats.Rmd`.

The imported data should be parsed and connected to the appropriate TA records so that timekeeping KPIs can be displayed throughout TAMS.

Use the current `week12_test_anonymized.xlsx` structure as the expected report format.

> Current test data will not necessarily match existing TA records. Build the system so matching and unmatched-record handling work correctly once production data is used.

---

## 1. Import Button

Add an **Import Time Stats** button to the appropriate area of the supervisor dashboard.

When clicked:

1. Open the operating system file explorer.
2. Allow `.xlsx` files only.
3. Let the supervisor select the generated `time_stats` report.
4. Read and validate the workbook.
5. Show an import preview before saving anything.

Do not automatically modify TA data immediately after file selection.

---

## 2. Expected Excel Tabs

The uploaded workbook may contain:

* `total_hours`
* `manual_entries`
* `above_21hrs`
* `pacing_report`
* `unsubmitted_hrs`
* `over_8hrs`
* `no_hrs`

The importer should detect available sheets instead of depending on sheet order.

Missing optional sheets should not crash the import.

---

## 3. TA Matching

Use `i_number` as the primary identifier for matching imported rows to existing TA records.

Do **not** use the TA name as the primary identifier.

Matching priority:

1. `i_number`
2. Existing TA/database relationship
3. Name only as a visible aid for resolving unmatched records

Never silently assign an unmatched row to a TA based only on a similar name.

---

## 4. Data Mapping

### `total_hours`

Map:

* `i_number`
* `max_assigned_hours`
* `total_hours_worked`
* `difference`
* `status`

Use this as the main weekly hours-performance source.

### `manual_entries`

Map:

* `i_number`
* `percentage_manual`
* `hours_inputted`
* `times_inputted`
* `user_or_mobile_entries`

Use this for the **Manual Entries** KPI/card.

### `above_21hrs`

Use this sheet to identify TAs who exceeded their assigned-hours threshold.

Map:

* `i_number`
* `total_hr`
* `max_assigned_hours`
* `over_assignment_by_1hr`

### `pacing_report`

Map:

* `i_number`
* `days_under_25_minutes`

Use this for pacing-policy calculations.

A TA appearing in this sheet has missed the pacing requirement during the selected week.

For the supervisor-level KPI:

**Pacing Policy Missing % = (Number of supervised TAs flagged for pacing ÷ Total supervised TAs) × 100**

Each TA should count only once toward the numerator.

Lower is better.

### `unsubmitted_hrs`

Map when valid data is available:

* `i_number`
* `total_hr`
* `status`

If the one-report version indicates that this information is unavailable, treat the KPI as **Unavailable**, not `0`.

### `over_8hrs`

Map:

* `i_number`
* `date`
* `daily_hours`

Use this to flag individual days where a TA worked more than 8 hours.

### `no_hrs`

Use this sheet to identify assigned TAs who recorded no hours for the week.

Do not interpret absence from this sheet as proof that all other timekeeping requirements were satisfied.

---

## 5. Weekly Data

Time Stats data must be stored **by week**.

Importing Week 13 must not overwrite Week 12.

The data model should support historical records such as:

```text
TA
 ├── Week 11
 │    └── Time Stats
 ├── Week 12
 │    └── Time Stats
 └── Week 13
      └── Time Stats
```

Use the application's existing project/database architecture and conventions rather than introducing a disconnected storage system.

---

## 6. Import Preview

Before committing the import, show a preview containing:

* File name
* Week being imported
* Number of TA records found
* Number successfully matched
* Number unmatched
* Any missing/unsupported sheets
* Validation errors or warnings

Provide:

**Cancel**

and

**Import**

Do not write to the database until the supervisor confirms **Import**.

---

## 7. Unmatched TAs

Unmatched records are expected during development.

Display them clearly in the preview.

Example:

```text
126 TA records found

Matched: 0
Unmatched: 126
```

The import itself should not crash because records cannot currently be matched.

Do not create new TA accounts automatically from an Excel import.

---

## 8. Dashboard Integration

After a successful import, use the imported weekly data to populate the existing TA and supervisor timekeeping UI where applicable.

Examples include:

* Total hours worked
* Difference from assigned hours
* Over / Under / Within status
* Manual-entry percentage
* Pacing-policy flag
* Pacing Policy Missing %
* Over-8-hour flags
* No-hours flags
* Unsubmitted-hours information when available

Avoid creating duplicate cards if an existing dashboard component already represents the KPI. Connect the imported data to the existing component instead.

---

## 9. Validation

The importer must:

* Accept `.xlsx` only.
* Validate expected sheet/column names.
* Handle empty sheets.
* Handle missing optional sheets.
* Reject files that are not recognizable Time Stats reports.
* Prevent malformed values from crashing the application.
* Never silently convert missing KPI data into `0`.
* Prevent duplicate imports for the same supervisor/week unless the user explicitly chooses to replace/update that week's data.

Show useful errors instead of raw exceptions.

---

## 10. UX

Follow the existing TAMS design system.

The flow should feel like:

**Import Time Stats → Select Excel → Validate → Preview → Confirm → Import Complete**

After completion, show a success state such as:

> **Week 12 Time Stats imported successfully.**

Include the number of matched and unmatched TA records.

---

## Implementation Requirements

Before implementing:

1. Inspect the existing TAMS architecture.
2. Identify the existing TA/profile database model.
3. Identify how weeks are currently represented.
4. Identify the dashboard components that should consume Time Stats data.
5. Reuse existing Supabase/database patterns, components, types, and styling.
6. Do not introduce a parallel architecture when existing structures can be extended.

Keep Excel parsing separate from database persistence so the importer can be maintained or changed later.

The final implementation should make the uploaded `time_stats` workbook the weekly source for TA timekeeping metrics while preserving historical weekly data.
